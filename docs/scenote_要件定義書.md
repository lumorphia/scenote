## 1. 概要

### 1.1 サービス名

**Scenote**

想定URL：

`https://scenote.lumorphia.com`

Lumorphiaブランド配下のサービスとして提供する。

---

## 2. サービスコンセプト

Scenoteは、**FINAL FANTASY XIV内で撮影した風景・日常・旅・記念撮影などのスクリーンショットを、手軽に現像し、記録・共有できるWebサービス**である。

単純なスクリーンショット投稿サービスではなく、

> 撮る → 現像する → 残す

という一連の体験をひとつのサービス内で完結させる。

ゲーム内で過ごした何気ない時間や、美しい場所を訪れた記録、フレンドとの記念撮影などを「作品」だけではなく「思い出」として保存できる場所を目指す。

---

## 3. Lumorphia内での位置付け

Lumorphiaは、画像を編集し、記録・共有するためのサービス群を提供するブランドとする。

| サービス          | 主な対象                             |
| ----------------- | ------------------------------------ |
| Prismtone         | ミラプリ・キャラクターコーディネート |
| Scenote           | 風景・日常・旅・複数人での記念撮影   |
| Facetia（構想中） | アクセサリー・ジュエリー・装飾品     |

画像編集機能は各サービス個別に実装せず、Lumorphia共通の画像編集基盤 (lumorphia/editor) を利用する。

```text
Lumorphia
│
├─ Prismtone ─ Lumorphia Editor
├─ Scenote   ─ Lumorphia Editor
└─ Facetia   ─ Lumorphia Editor
```

編集画面を独立サービスとして意識させるのではなく、各サービスの投稿フローの中にEditorを組み込む。基本の流れは次のとおり。

```text
Scenote → 画像を選択 → 編集 → Scenoteへ投稿
```

Editor単独アプリからScenoteへ送る導線 (lumorphia/editor#6) は、あれば使えるが、Scenoteの基本フローには含めない。

---

## 4. Prismtoneとの棲み分け

### Prismtone

**「何を着ているか」を残すサービス。** 投稿の中心情報は「キャラクターと装備」。

主な対象：ミラプリ、キャラクター単体、装備、染色、コーディネート、装備情報を伴うスクリーンショット。

### Scenote

**「どこで、どんな時間を過ごしたか」を残すサービス。** 投稿の中心情報は「写真とその場面」。

主な対象：風景、景色、街並み、ハウジング、日常の一場面、旅の記録、フレンドとの記念撮影、複数キャラクターの写真、イベントの記録、思い出として残したいスクリーンショット。

### 判断基準

> 新しく作ったミラプリを見せたい → Prismtone
>
> 新しいミラプリを着てフレンドとイル・メグへ遊びに行った写真を残したい → Scenote

完全な排他関係にはせず、ユーザー自身が「何を主役として投稿したいか」で選択する。

Prismtoneは風景のみの投稿を禁止している (Prismtone の運営上の決定)。その受け皿がScenoteになるため、両方の規約・投稿画面から互いを案内する。

---

## 5. 想定ユーザー

- FFXIVでスクリーンショットを撮るユーザー
- グループポーズを利用するユーザー
- SNSへスクリーンショットを投稿しているユーザー
- Lightroom等を使うほどではないが、写真を少し綺麗にしたいユーザー
- ゲーム内の旅や出来事を記録しておきたいユーザー
- フレンドとの記念写真を残したいユーザー
- スクリーンショットを後から振り返りたいユーザー

高度な画像編集知識を持っていないユーザーでも利用できることを重視する。

---

## 6. 基本ユーザーフロー

### 6.1 投稿

```text
Scenoteを開く → 画像を選択 → Lumorphia Editorで編集 → 投稿情報を入力 → プレビュー → 投稿
```

可能な限り画面遷移を少なくする。

### 6.2 閲覧

```text
Scenoteを開く → 投稿一覧 → 気になる写真を選択 → 投稿詳細
```

写真そのものを中心としたUIとする。

## 7. 画像アップロード

### 必須

- ドラッグ＆ドロップ
- ファイル選択
- 画像プレビュー
- 対応形式チェック
- ファイルサイズチェック
- 画像サイズチェック
- 不正な画像の拒否

### 対応形式

PNG、JPEG、WebP。

### 上限

Editor・Prismtoneと同じ値にする。

| 項目                           | 上限                       | 定義元                                                                             |
| ------------------------------ | -------------------------- | ---------------------------------------------------------------------------------- |
| 読み込むファイル               | 30 MB                      | `@lumorphia/editor-engine` の `MAX_UPLOAD_BYTES`                                   |
| サーバーが受け取る画像の画素数 | 5,000 万画素、長辺 8192 px | Prismtone の `MAX_INPUT_PIXELS` / `MAX_INPUT_EDGE` (共通化後は `@lumorphia/media`) |

ブラウザで書き出した画像を受け取るので、サーバーに届くのはWebP (なければJPEG) になる。

## 8. 画像編集

Lumorphia Editor (lumorphia/editor) を利用する。Scenote固有の実装はしない。

| パッケージ                 | 役割                               |
| -------------------------- | ---------------------------------- |
| `@lumorphia/editor-recipe` | 編集レシピ (zod)。サーバーでも使う |
| `@lumorphia/editor-engine` | 状態、描画、推論、下書き           |
| `@lumorphia/editor-react`  | 編集画面。`<Editor host={...} />`  |

Scenoteは編集ページに `<Editor>` を置き、`EditorHost.destinations` に「Scenoteへ投稿」を 1 件渡す。ホストとして満たすこと (オリジンの分離、CSP、モデル配信、CSS、Vite) は editor の ADR-0009 に従う。

### 8.1 基本補正

| 項目                                                                              | 状況                                                                                               |
| --------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| 露出、コントラスト、彩度 (自然な彩度を含む)、色温度、色合い、ハイライト、シャドウ | Editor に実装済み                                                                                  |
| 白レベル、黒レベル、シャープネス (全体)                                           | Editor に未実装。レシピ v5 として Editor に追加する (Prismtone にも効く)。MVP の公開条件にはしない |

Editor側で追加された機能は、Editorの版を上げればScenoteでも使える。

### 8.2 プリセット

Editorの既存プリセット (夜景、夕暮れ、朝霧、パステル、ビビッド、フィルム風、モノクロ、ソフト、ダンジョン、ゴールド) を使う。風景向きのものが多く、初版の案 (Natural / Warm / Cool / Vivid / Cinematic / Night / Soft) はおおむね含まれる。

Scenote向けに並び順や表示する組を変えたくなったら、Editorに任意の設定 (`EditorHost.presets` など) を足す。実画像で試してから決める。

プリセット適用後も各パラメータを個別調整できる (Editor 実装済み)。

### 8.3 Before / After

Editorの比較スライダーで、編集前と編集後を切り替えられる (Editor 実装済み)。

### 8.4 編集状態と再編集

編集レシピは版付きのJSONで、シリアライズできる (Editor 実装済み)。投稿にはレシピを添えて保存する。

**原本はサーバーに保存しない** (Prismtone と同じ)。保存費用と、他人のキャラクター名などが写った原本を預かる責任を避ける。再編集は次の手段で行う。

| 手段                                                | 範囲                                                                                                                                             |
| --------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| 端末の下書き (IndexedDB)                            | 同じ端末・同じブラウザ                                                                                                                           |
| 再編集用WebP (prismtone#352 の方式を Editor に実装) | 利用者が「元画像を含めて保存」にチェックしたときだけ、元画像とレシピを同梱したWebPを端末に保存する。そのファイルを開けば別の端末でも再編集できる |

将来の「編集設定の再利用」「プリセットとして保存」は、DBに残したレシピを使う。

## 9. 投稿

編集した画像をScenoteへ投稿する。**1 投稿 1 枚**。複数枚をまとめる機能はアルバム (23 章) で扱う。

| 項目           | 必須              | 補足                    |
| -------------- | ----------------- | ----------------------- |
| 投稿画像       | 必須              | Editor で書き出した画像 |
| 公開範囲       | 必須 (既定値あり) | 下記                    |
| タイトル       | 任意              |                         |
| 本文／コメント | 任意              |                         |
| 撮影場所       | 任意              | 10 章                   |
| タグ           | 任意              | 11 章                   |
| 撮影日         | 任意              | 下記                    |

入力項目を増やしすぎず、画像だけでも投稿できる設計を基本とする。

### 9.1 公開範囲

| 値       | 一覧・タグ検索・利用者ページ | 投稿 URL               | 画像 URL                           | OGP      |
| -------- | ---------------------------- | ---------------------- | ---------------------------------- | -------- |
| 公開     | 出る                         | 誰でも見られる         | 公開                               | 出す     |
| 限定公開 | 出ない                       | URL を知る人が見られる | 推測できない URL                   | 出す     |
| 非公開   | 出ない                       | 本人以外は 404         | 本人だけが読める短命の署名付き URL | 出さない |

非公開は「自分の記録」として残すためのもの。Prismtoneの private (一覧に出ないだけで URL を知れば見える) とは意味が違う。既定値は投稿画面で選びやすい形にし、何を選んだかが一目で分かるようにする。

### 9.2 撮影日

タイムライン (23 章) と「後から見返す」(24 章) の土台。後から全件に付け直すことはできないので、MVPから項目を持つ。

- 既定値はブラウザが読んだファイルの更新日時。ファイル名からは読み取らない
- 利用者が変更・削除できる
- EXIF の撮影日時は使わない (FFXIV のスクリーンショットには通常含まれず、メタデータは削除する方針のため)

## 10. 撮影場所

投稿にFFXIV内の撮影場所を設定できる。地域 → エリアの 2 階層で持つ。

```text
ラノシア
└─ リムサ・ロミンサ

イル・メグ

オールド・シャーレアン
```

MVPでは自由入力と候補選択の両方を受け付ける。候補はXIVAPIの地名データを同期してDBに持ち、外部APIを投稿のたびに呼ばない (Prismtone ADR-0008 の考え方)。候補から選んだ場所は ID で、自由入力はテキストで保存する。

将来的にはマップデータと連携し、エリア別ギャラリーなどへ広げる。

## 11. タグ

投稿へ任意のタグを設定でき、タグから投稿を検索できる。

```text
#風景 #夜景 #夕焼け #ハウジング #フレンド #記念撮影 #旅
```

検索結果に出るのは公開の投稿だけ。

## 12. 投稿一覧

写真を中心とした一覧画面を提供する。Pinterestや写真ギャラリーに近い、縦横比を保った並べ方にする。

表示内容：サムネイル、タイトル、投稿者、投稿日、タグ。UIではメタ情報より写真を優先する。

## 13. 投稿詳細

画像、タイトル、コメント、投稿者、撮影場所、タグ、撮影日、投稿日を表示する。画像をできるだけ大きく表示する。

## 14. アカウント

Lumorphia アカウント (accounts.lumorphia.com) でログインする。Scenote 単独の登録は設けない。

- handle、表示名、アイコン、キャラクター (Lodestone の確認) は Lumorphia アカウントのものを使う
- 規約の同意、BAN、Scenote だけの退会は Scenote が持つ
- Lumorphia アカウントの設計と Prismtone からの移行は `lumorphia/accounts/docs/plan.md`

## 15. マイページ

自分の投稿 (公開範囲を問わず全件) を一覧表示する。

MVP：投稿一覧、投稿詳細、投稿削除。

将来：投稿編集、お気に入り、コレクション、プリセット管理。

## 16. シェア

MVP：投稿URLコピー、OGP。

OGPでは投稿画像を大きく表示する (summary_large_image)。X等へURLを貼った際に、写真そのものが魅力的に表示されることを重視する。非公開の投稿はOGP画像を出さない。

## 17. レスポンシブ対応と言語

PC、タブレット、スマートフォンをサポートする。編集はPCを主なユースケースとするが、スマートフォンから投稿・閲覧できない設計にはしない。

MVPの表示言語は日本語のみ。Editorは日本語と英語を持つので、英語は後から足せる。

## 18. 非機能要件

### 18.1 パフォーマンス

一覧表示時に大きな画像を直接読み込ませない。受け取った書き出し画像から用途別の画像を生成し、受け取った画像は生成後に削除する。

```text
display    詳細表示用
thumbnail  一覧用
ogp        共有用 (1200x630 前後)
```

形式はWebPを基本とする (OGP は対応状況に合わせて JPEG)。

### 18.2 ストレージ

画像はオブジェクトストレージ (Cloudflare R2、Prismtone と同じ構成) へ保存する。ブラウザから署名付きURLで直接置き、アプリケーションサーバーのローカルディスクへ永続保存しない。バケットはPrismtoneと分ける。

### 18.3 セキュリティ

- MIME Type検証
- ファイルサイズ制限
- 画像デコード検証 (画素数上限つき)
- 再エンコードによるメタデータ・拡張チャンクの除去
- XSS対策
- CSRF対策
- 認可チェック (公開範囲を含む)
- アップロードファイル名を信用しない

画像の検証と派生画像の生成は、Prismtoneと共通のパッケージ (`@lumorphia/media`、仮称、ADR-0006) にする。2 つのサービスで処理が食い違わないようにするため。

## 19. プライバシー

### 19.1 メタデータ

投稿画像はサーバーで再エンコードし、EXIF等のメタデータは残さない。再編集用WebP (8.4) の同梱データも、投稿経路では再エンコードで除かれ、公開配信されない。テストで確かめる。

編集レシピは画像に埋め込まず、DBに保存する。

### 19.2 写り込んだ他人

記念撮影やイベントの写真には、フレンドや他のプレイヤーのキャラクター名、FC 名、チャット欄が写る。

- 投稿画面に「他の人が写っている場合は、本人の了承を得てください」と表示する
- 名前などを隠す手段として、Editorの部分補正 (ぼかし) が使えるかを試し、足りなければEditor側で検討する
- 削除依頼は通報 (26 章) から受け付ける

## 20. アーキテクチャ方針

ScenoteとPrismtoneを同一アプリケーションへ統合しない。それぞれ独立したサービス (別リポジトリ、別 DB、別デプロイ) として管理する。

```text
lumorphia/
├─ prismtone
├─ scenote
├─ accounts  Lumorphia アカウント (ログイン、handle、キャラクター)
├─ editor    現像 (@lumorphia/editor-*)
├─ platform  共通基盤、public (@lumorphia/media、storage、auth-client、ops、legal、開発の道具。仮称)
└─ umbra     共通基盤、private (@lumorphia/moderation)
```

構成はPrismtoneに準じる (React Router SSR + Fastify、PostgreSQL + Drizzle、pg-boss、R2、Docker Compose)。ログインは Lumorphia アカウントの OIDC を使う。

### 共通化の範囲

サービスの領域に属さない基盤は、Scenote を始める前に共通パッケージにする (ADR-0006)。Scenote の開始が遅れることは受け入れる。

| 対象                                                                                                     | 方針                                                      |
| -------------------------------------------------------------------------------------------------------- | --------------------------------------------------------- |
| 現像                                                                                                     | `@lumorphia/editor-*` を使う                              |
| ログイン                                                                                                 | Lumorphia アカウント (14 章) と `@lumorphia/auth-client`  |
| 画像の検証・派生画像・OGP の描画、ストレージとアップロード、モデレーション、運用、規約の同意、開発の道具 | `lumorphia/platform` (public) と `umbra` の共通パッケージ |
| 投稿、タグ、検索、一覧、通報と管理画面                                                                   | Prismtone から写して始める。2 つが動いてから見直す        |

### Editor の責務

含める：画像読み込み、画像処理、パラメータ管理、プリセット、Render、編集設定のシリアライズ。

含めない：Scenote/Prismtone固有UI、投稿、認証、DB、SNS機能。

## 24. Scenoteが重視するもの

1. **写真が主役であること** — UIそのものが写真より目立たない
2. **編集が難しくないこと** — Lightroomを知らなくても使える
3. **投稿が面倒ではないこと** — 項目を大量に入力させない
4. **日常の写真でも投稿できること** — 「作品でなければ投稿してはいけない」という雰囲気を作らない
5. **後から見返したくなること** — タイムラインとして消費するだけでなく、「自分の記録」として残る。非公開でも残せる

---

## 25. プロダクトとしての核

Scenoteが提供したい価値は、**綺麗な写真を投稿することだけではない。**

FFXIVで過ごしていると、

- なんとなく綺麗だった景色
- フレンドと遊んだ夜
- 偶然撮れた一枚
- 初めて訪れた場所
- 何でもない日常

のような写真が大量に生まれる。それらはSNSへ投稿しなければ、そのままスクリーンショットフォルダへ埋もれていく。

Scenoteは、それらを少しだけ綺麗にして、ひとつの記録として残す場所を作る。

**Scene + Note。**

特別な作品だけではなく、**そのとき、その場所にいたことを残す。**
