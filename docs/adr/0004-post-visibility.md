# ADR-0004: 公開範囲を 公開 / 限定公開 / 非公開 の 3 段階で MVP から持つ

| 項目     | 内容       |
| -------- | ---------- |
| Status   | Accepted   |
| Date     | 2026-10-06 |
| Deciders | t1nyb0x    |

## Context

要件定義書の初版には公開範囲が無く、すべて公開だった。一方で 24 章は「自分の記録として残る」ことを重視している。記念撮影には他のプレイヤーが写るので、全体に公開するのをためらう利用者がいる。

prismtone の `private` は一覧・検索に出ないだけで、URL を知っていれば画像も投稿も見える。

## Decision

投稿に公開範囲 `public` / `unlisted` / `private` を持たせ、MVP から使えるようにする。

| 値         | 一覧・タグ検索・利用者ページ | 投稿 URL     | 画像                         | OGP      |
| ---------- | ---------------------------- | ------------ | ---------------------------- | -------- |
| `public`   | 出る                         | 誰でも       | 公開 URL                     | 出す     |
| `unlisted` | 出ない                       | URL を知る人 | 推測できない公開 URL         | 出す     |
| `private`  | 出ない                       | 本人以外 404 | 本人だけに短命の署名付き URL | 出さない |

- `private` の画像は公開配信のパス (カスタムドメイン) に置かず、別のプレフィックスに置いて署名付き URL だけで読ませる
- 公開範囲を変えたら、画像を置き場所の間で移すジョブを投入する。移し終えるまで、詳細は新しい範囲で認可する
- 認可は API の 1 か所 (投稿を読む関数) で行い、一覧・詳細・OGP・画像 URL の発行が同じ判定を使う

## Consequences

### 良い点

- 非公開の記録としても使える。「作品でなければ」の空気を和らげる
- 他人が写った写真を、限定公開でフレンドにだけ見せられる

### 悪い点・受け入れるリスク

- prismtone と `private` の意味が違う。共通化 (ADR-0006) のときに名前で混同しない
- 公開範囲の変更で画像の移動が要り、ジョブが増える

### 追従して必要になること

- E2E で、他人が `private` の投稿・画像 URL・OGP を読めないことを確かめる
- Cloudflare のキャッシュに `private` の応答が載らないようにする

## Alternatives

- 公開だけ: いちばん小さいが、記録として使えない
- prismtone と同じ 2 段階 (public / private = 限定公開): 「自分だけ」が無い
