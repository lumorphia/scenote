# ADR-0020: 保留・要確認の投稿は運営が理由を書いて公開か非表示に決め、非表示は本人にだけ見せる

| 項目     | 内容       |
| -------- | ---------- |
| Status   | Accepted   |
| Date     | 2026-10-17 |
| Deciders | t1nyb0x    |

## Context

自動モデレーション (ADR-0014) は、投稿を `clear` / `flagged` / `held` に振り分ける。`held` は公開せず本人にだけ見せ、`flagged` は公開したまま運営があとで確かめる。どちらも、運営が確かめる画面を S7 に回していた。管理画面の守りと操作の記録は ADR-0019 で決めた。

## Decision

- 確認待ちは「保留 (`held`)」と「要確認 (`flagged`) で公開中のうち、まだ確かめていないもの」。管理画面に古い順に並べる。運営には判定の内訳 (labels) も見せる (画面とアプリの中だけで、しきい値はリポジトリに書かない。ADR-0007)
- 運営は理由を書いて、次のどちらかに決める。理由は必須で、操作と同じトランザクションで記録する (`post_approved` / `post_hidden`)。行は `FOR UPDATE` し、もう待っていない投稿は `conflict`
  - **公開する**: 保留なら `published` にして公開日時を入れ、画像を公開範囲どおりの置き場所へ移す (`image-move`)。非公開の投稿は非公開の置き場所のまま。要確認なら、確かめた印 (`reviewed_at`) を付けるだけ
  - **非表示にする**: 新しい状態 `hidden` にする。画像は非公開の置き場所へ移す。`canView` は `published` でなければ本人にしか見せないので、`hidden` は本人にだけ見え、一覧・タグ・利用者のページ・OGP からも外れる。本人のページには「運営により非表示」と出し、理由は出さない
- `hidden` と `held` は「画像を非公開の置き場所に置く状態」(`keepsImagesPrivate`) としてまとめる。どちらも、本人が公開範囲を変えても画像を動かさない
- 保留の画像は非公開の置き場所にあり、`canView` では運営にも見えない。管理画面には運営だけが通る画像の中継 (`/api/admin/posts/:id/image/:variant`、`private, no-store`) を置く
- 非表示を戻す操作は、通報の対応と一緒に S7b で決める

## Consequences

### 良い点

- 保留された人の投稿が、運営が見れば公開される。誤って保留された正規の写真を救える
- 非表示にしたものは公開の置き場所から消え、CDN にも新しく載らない

### 悪い点・受け入れるリスク

- 本人に非表示の理由を伝えない。問い合わせで受ける (S7d の規約に書く)
- 非表示にした直後も、公開の画像は CDN に最大 1 時間残りうる (ADR-0012 と同じ)

### 追従して必要になること

- S7b: 通報の対応で、公開中の投稿を非表示にする・戻す
- S7d: 規約に、運営が非表示にできることと、問い合わせ先を書く

## Alternatives

- 却下した投稿を消す: 本人の記録まで消える。非公開の記録としては残せるよう、非表示にとどめる
- 要確認を公開しないで待つ: 誤検出のたびに公開が遅れる。自動の判定 (ADR-0014) のとおり、要確認は公開したまま確かめる
