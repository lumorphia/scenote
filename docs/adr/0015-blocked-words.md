# ADR-0015: タイトル・本文・タグ・撮影場所の NG 語は、画像を送る前に確かめ、サーバーで必ず断る

| 項目     | 内容       |
| -------- | ---------- |
| Status   | Accepted   |
| Date     | 2026-10-17 |
| Deciders | t1nyb0x    |

## Context

lumorphia/prismtone は、タイトル・説明・タグを NG 語の一覧と照合して、当たったら投稿を断っている (prismtone の RM-21)。一覧と照合は `@lumorphia/moderation/text` (lumorphia/umbra、private) に切り出してある (prismtone ADR-0060)。語の一覧は知られると回避されるので、このリポジトリにも利用者のブラウザにも置かない (ADR-0007)。

Scenote の投稿は、受け取りの枠をもらい、画像を PUT してから、書いたものと一緒に投稿を作る (ADR-0011)。投稿を作るときに初めて断ると、枠と送った画像が無駄になる。1 人が使っていない枠は 10 個までなので、書き直して送るたびに減っていく。

## Decision

- 照合するのは、タイトル・本文 (ひとこと)・タグ・自由入力の撮影場所。候補から選んだ撮影場所は照合しない。照合の決まり (表記のゆれをそろえる、タイトルと本文は部分一致) はパッケージのもので、自由入力の撮影場所は本文と同じ部分一致で見る (`packages/core/src/domain/blocked-text.ts`)
- 一覧は S5g ではパッケージの組み込みだけを使う。運営が足す辞書の表と管理画面は S7 で足し、組み込みと合わせて照合する
- サーバーは、投稿の作成とタグ・撮影場所の付け直しで必ず照合し、当たったら `validation` で断る。応答の `error.issues` に当たった欄 (`title`・`body`・`tags`・`placeText`) だけを入れ、どの語に当たったかは返さない。投稿の作成では、受け取りの枠を使う前に断る
- 投稿画面は、画像を送る前に `POST /api/posts/check-text` で確かめ、当たったら枠をもらわずに止める。この API もログインが要り、欄だけを返す
- 画面は欄の名前で「〇〇に使えない語が含まれています」と出す。web は `@lumorphia/moderation` を import しない (ADR-0014 の ESLint の決まり)
- テストの語はパッケージの一覧から取り、リポジトリに書かない

## Consequences

### 良い点

- Prismtone と同じ一覧と決まりで、2 つのサービスで断る語が食い違わない
- 書き直すたびに受け取りの枠が減ることが無い

### 悪い点・受け入れるリスク

- `check-text` を何度も叩けば、どの語が断られるかを探れる。ログインを要求し、1 分に 60 回までにする。Prismtone も同じ口を持っていて、照合した結果は投稿の作成でも分かるので、この口を閉じても探れることは変わらない
- 運営が足す辞書が無い間は、組み込みの最小限の語だけで断る。公開は S7 のあとなので、利用者に出る前には揃う

### 追従して必要になること

- S7: NG 語の辞書の表と管理画面 (prismtone の `blocked_terms`)、照合に合わせる

## Alternatives

- 投稿の作成のときだけ断る: 実装は少ないが、書き直すたびに受け取りの枠と送った画像が無駄になる
- 語の一覧をブラウザに配って、その場で確かめる: 通信は減るが、一覧が誰にでも読める (ADR-0007)
- 投稿を作ってから NG 語を保留にする (画像と同じ): 書いた本人に直してもらえば済むものを、運営の確認に回すことになる
