# ADR-0003: 原本はサーバーに保存せず、再編集は端末と再編集用 WebP で行う

| 項目     | 内容       |
| -------- | ---------- |
| Status   | Accepted   |
| Date     | 2026-10-06 |
| Deciders | t1nyb0x    |

## Context

要件定義書の初版は、派生画像に `original` を挙げ (18.1)、「過去写真の再編集」を将来の拡張に挙げていた (8.4)。再編集には原本が要る。

prismtone は原本を保存しない (prismtone ADR-0006)。理由は保存費用と権利上の懸念。Scenote では記念撮影が主な対象で、原本にはフレンドや他のプレイヤーのキャラクター名、チャット欄、トリミングで外した範囲が写る。預かる責任は prismtone より重い。

prismtone#352 で、元画像と編集レシピを同梱した WebP を、利用者がチェックしたときだけ端末に保存する案が出ている。

## Decision

- 原本はサーバーに保存しない。ブラウザで書き出した画像を受け取り、display / thumbnail / ogp を作ったら、受け取った画像は消す
- 編集レシピ (`@lumorphia/editor-recipe`) は投稿に添えて DB に保存する。画像には埋め込まない
- 再編集は次の 2 つで行う
  - 端末の下書き (IndexedDB、名前は `scenote-drafts` で固定)
  - 再編集用 WebP: prismtone#352 の方式を lumorphia/editor に実装し、Scenote はそれを使う。既定は OFF、利用者がチェックしたときだけ端末に保存する。投稿にはしない
- 投稿経路の再エンコードで、EXIF と WebP の拡張チャンク (同梱した元画像を含む) が残らないことをテストで確かめる

## Consequences

### 良い点

- 保存費用と、他人が写った原本を預かる責任を持たない
- 再編集用 WebP なら別の端末でも再編集できる。データの持ち主は利用者

### 悪い点・受け入れるリスク

- 再編集用 WebP を保存しなかった利用者は、別の端末から再編集できない
- 再編集用 WebP は Editor の機能で、Scenote の公開には間に合わないかもしれない。その間の再編集は同じ端末だけ

### 追従して必要になること

- lumorphia/editor に prismtone#352 を移し、実装する
- 投稿画面の説明に「原本は保存しない」ことを書く

## Alternatives

- 原本を非公開で保存する: 別の端末から再編集できるが、費用と責任が増える。削除依頼の対応範囲も広がる
- 利用者が投稿ごとに選ぶ: 上の 2 つの短所を両方持ち、説明も増える
