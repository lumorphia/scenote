# ADR-0017: 投稿の削除はすぐに行を消し、画像は worker が消す

| 項目     | 内容       |
| -------- | ---------- |
| Status   | Accepted   |
| Date     | 2026-10-17 |
| Deciders | t1nyb0x    |

## Context

要件定義書 15 章は、マイページで自分の投稿を一覧し、消せることを MVP に含めている。Scenote は原本を持たず (ADR-0003)、投稿の画像は派生画像だけ。退会の物理削除 (ADR-0010) は、行を消すのと同じトランザクションで `image-delete` ジョブに画像を渡している (ADR-0011)。

## Decision

- 本人が投稿を消すと、行をすぐに消し、同じトランザクションで `image-delete` に画像のキーの頭を渡す。公開範囲を変えて画像を移している途中なら、行き先も渡す。猶予や復旧は持たない (画面で一度確かめてから消す)
- タグとの結び付きは行と一緒に消える。どの投稿にも使われなくなったタグは、これまでどおり毎時の掃除が消す
- 派生画像を作っている途中で投稿が消されたら (本人の削除、退会の物理削除)、`image-process` は投稿の行を書き換えられなかったことで気づき、置いた画像を消す。これまでは画像が残っていた
- マイページ (`/me`、`GET /api/me/posts`) は、自分の投稿を公開範囲も状態も問わず、作った順の新しい順に返す。続きは (作った日時, ID) のカーソルで、一覧 (ADR-0016) と同じ形 (`domain/cursor.ts`)。応答は `private, no-store`

## Consequences

### 良い点

- 消したものはすぐに誰からも見えなくなり、画像もストレージに残らない
- 退会の物理削除と同じ仕組みなので、消し方が 1 つで済む

### 悪い点・受け入れるリスク

- 間違えて消しても戻せない。確かめる手順を挟む
- 公開の画像は配信元 (CDN) に最大 1 時間残りうる (`max-age=3600`、ADR-0012 と同じ)

### 追従して必要になること

- S7: 運営による非表示・削除は、通報と管理画面で別に決める

## Alternatives

- 論理削除して、しばらく後に物理削除する (lumorphia/prismtone の形): 戻せるが、消したものを見せない条件があちこちに要る。MVP では採らない
