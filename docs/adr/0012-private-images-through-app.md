# ADR-0012: 非公開の投稿の画像は、アプリが本人にだけ返す

| 項目     | 内容       |
| -------- | ---------- |
| Status   | Accepted   |
| Date     | 2026-10-12 |
| Deciders | t1nyb0x    |

## Context

ADR-0004 は、非公開の投稿の画像を「本人だけに短命の署名付き URL」で見せると決めた。S5c で作るときに、`@lumorphia/storage` には読み取り用の署名付き URL が無いと分かった。足すには platform の変更と公開、開発の `/_storage` での署名の検証が要る。

署名付き URL は、期限までは URL を知っていれば誰でも読める。非公開の画像は本人しか見ないので、数は少ない。

## Decision

非公開の投稿の画像は、アプリが `GET /api/posts/:id/image/{display|thumb}` で、ログインと本人を確かめてから返す。ADR-0004 の「短命の署名付き URL」の一文をこれで置き換える。ほかは ADR-0004 のまま。

- 画像の置き場所は、公開・限定公開は `posts/{postId}/{推測できない値}/`、非公開は `private/{postId}/{推測できない値}/`
- 中継の応答は `cache-control: private, no-store`。非公開の画像はストレージにも `private, no-store` で置く
- 見られるかの判定は `canView` (`packages/core/src/domain/posts.ts`) の 1 か所。投稿の API、画像の中継、これからの一覧と OGP が同じ判定を使う。本人はいつでも、ほかの人は「画像ができていて、投稿者が退会中でなく、非公開でない」ときだけ
- 公開範囲を変えたら、見られるかは新しい範囲ですぐに決まる。画像は `image-move` ジョブが新しい推測できないキーに移し、古いものを消す。限定公開から公開のように同じ置き場所の中でもキーを変えるので、古い画像の URL は使えなくなる。移している間は、今ある置き場所から読む (非公開の置き場所にあれば中継を指す)

## Consequences

### 良い点

- platform を変えずに済む。URL が漏れても、本人以外は読めない
- 判定が 1 か所なので、一覧や OGP を足すときに抜けにくい

### 悪い点・受け入れるリスク

- 非公開の画像だけはアプリのサーバーを通る (display は長辺 2048 px の WebP)
- 公開から非公開に変えた直後は、移し終えるまでの数秒、古い公開の URL がまだ読める。CDN には最大 1 時間残りうる (`max-age=3600`)。古い URL を知っている人に限られる
- R2 のカスタムドメインはバケット全体を配る。`private/` も、キーを知っていれば配信元から読めてしまう。キーには推測できない値が入っているが、本番 (S7) では配信元で `private/` を拒む (Cloudflare のルール) か、非公開の画像を別のバケットに置く

### 追従して必要になること

- S7: 配信元で `private/` を拒む
- S6: 一覧・詳細・OGP で `canView` を使う

## Alternatives

- `@lumorphia/storage` に `presignGet` を足して署名付き URL を出す (ADR-0004 のまま): 画像はアプリを通らないが、platform の変更と公開を待つ。期限まで URL を知る人は誰でも読める
- 非公開でも公開の置き場所に置き、推測できない URL だけで守る: 限定公開と変わらなくなる
