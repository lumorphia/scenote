# ADR-0022: 運営が足す NG 語は DB の辞書に置き、組み込みの一覧と合わせて照合する

| 項目     | 内容       |
| -------- | ---------- |
| Status   | Accepted   |
| Date     | 2026-10-18 |
| Deciders | t1nyb0x    |

## Context

ADR-0015 で、タイトル・本文・タグ・自由入力の撮影場所を `@lumorphia/moderation/text` の組み込みの一覧 (最小限) と照合すると決め、運営が足す辞書と画面を S7 に回した。NG 語の辞書は知られると回避されるので、リポジトリには置かない (ADR-0007)。lumorphia/prismtone は `blocked_terms` の表と管理画面で同じことをしている (prismtone ADR-0060)。

## Decision

- 表 `blocked_terms` に語・表記をそろえた形 (`normalizeForBlocklist`、一意)・照合のしかた (`contains` 部分一致 / `exact` 語全体)・辞書の名前 (手で足したものは `manual`)・使うか (`enabled`) を置く。prismtone と同じ形
- 照合 (`checkText`) は、組み込みの一覧と、使う語を合わせて行う。合わせたものはプロセスの中に 30 秒置き、管理画面で変えたらすぐ捨てる。投稿の作成・付け直し・送る前の確かめ (`check-text`) の全部がこれを通る
- 管理画面の「NG 語」で、1 語を足す、辞書 (1 行 1 語、`#` はコメント) をまとめて入れる (1 回 20,000 語、1 語 64 文字まで、あった語は飛ばす)、止める・使う、消す
- どの操作も理由が必須で、同じトランザクションで記録する (ADR-0019)。記録には語そのものは書かず、語の ID か辞書の名前で指す。画面ではタブの上の 1 つの理由の欄を、そのタブの操作に使う
- テストの語はテストの中で作り、本物の辞書の語を書かない

## Consequences

### 良い点

- 運営が、回避された語や新しい語をすぐ足せる。辞書はリポジトリにも利用者のブラウザにも出ない
- Prismtone と同じ形なので、片方で使った辞書をもう片方にも入れられる

### 悪い点・受け入れるリスク

- 30 秒のキャッシュがあるので、worker などほかのプロセスで照合するようになったら、変更が効くまで最大 30 秒かかる (今はアプリだけが照合する)
- 語を足しても、もう投稿された文は調べ直さない。見つけたら通報か管理画面で扱う

## Alternatives

- 辞書をファイルにして配る: 運営がすぐ足せず、リポジトリに入れられない (ADR-0007)
- 足した語で既存の投稿を調べ直して自動で隠す: 部分一致の誤りで、関係の無い投稿まで隠しうる
